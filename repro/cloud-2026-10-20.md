# Cloud stranger repro: atlas-station, 2026-10-20

**Verdict: PARTIAL**

The README quickstart works as written. `npm ci` and `npm test` pass on a clean Linux VM, and `npm test` needs no network and no API key; I confirmed that with networking turned off. The Work-Eater, `inspect_source`, and obligation-diagnostic commands also run and exit 0.

Three parts of the README do not hold for a stranger:

- The "Verify v1" commands (`v1:status`, `v1:verify`, `v1:release`) cannot pass on any machine. Their own documentation check rejects the current README, and they require a Codex CLI that the README says is disabled.
- `npm start` launches the window but never starts the fleet sidecar unless Node is installed at `C:\Program Files\nodejs\node.exe` or an undocumented `NODE_BIN` variable is set.
- The full test surface that CI runs needs three sibling repositories, three environment variables, and `CI=true`. The README mentions none of them.

I mirrored that CI setup by hand, and then the full `npm run test:full` chain passed on Linux in 21.9 seconds.

I changed no source file. This report is the only file added.

## Environment

- **Date:** 2026-10-20. Run started 03:25:03 UTC.
- **Machine:** Ubuntu 24.04.5 LTS, Linux 6.18.44, x86_64, 4 vCPU, 15 GiB RAM. The session runs as root by default.
- **Commit under test:** `e6163138d490f2c495f639c39913985c5d9df7c1`. This is `origin/master` ("shard-seal test: require sibling module by relative path"). The clone was shallow.
- **Node, preinstalled:** v22.22.0 with npm 10.9.4.
- **Node, to match the README:** v24.22.0 with npm 11.19.1, installed with nvm from nodejs.org because the README requires Node.js 24. Every result below is from Node 24 unless it says otherwise. `npm test` and the quick commands gave the same results on Node 22.
- **Python:** 3.13.16. The README says "Python 3"; CI uses 3.12.
- **Network:** outbound traffic goes through a policy proxy. It allowed the npm registry, nodejs.org, git clones from GitHub, PyPI, and the Electron binary download. It denied `www.sec.gov` and `algora.io`: curl through the proxy got `CONNECT tunnel failed, response 403`, and Node's built-in fetch reported `fetch failed`. The Hugging Face embedding model download also failed with `fetch failed`. This is a limit of my VM, not a repository defect.
- **Display:** none. I used `xvfb-run` for Electron. Electron refuses to run as root without `--no-sandbox`, so I reran the Electron checks as a non-root user (`stranger`) in a fresh `git clone` of the same commit.

## Full test surface, suite by suite

`test:full` chains every suite with `&&`, so the first failure hides the rest. I therefore ran each of its 38 component scripts separately. This run used Node 24, root, xvfb, and no extra environment, as a stranger would by default.

- **30 of 38 exited 0.** `test:fleet` counts among them, but it only prints `SKIP: no provider credentials configured`. CI does the same.
- **8 exited 1:**
  - `test:proposal-audit` (gap 6)
  - `test:causal-xenosoma`, `test:independent-receipts`, `test:wing:d2`, `test:wing:felt`, `test:mission`: all five look for `E:/boundary`, `E:/recursive-discovery-engine` or `E:/director2-harness` (gap 5)
  - `test:renderer:live` and `test:renderer:visual`: Electron refuses to run as root

Each failure cleared once its condition was removed:

- **Electron:** as the non-root user under xvfb, `test:renderer:live` passed in 5.3 s and `test:renderer:visual` in 3.0 s. The visual test only writes its committed PNG when `ATLAS_VISUAL_CAPTURE=1`, so it did not dirty the tree.
- **Sibling repos:** I cloned NexumCorpus/boundary @ `c2b925e`, NexumCorpus/recursive-discovery-engine @ `8b317fd` and NexumCorpus/director2 @ `f5bd0cb`. These are the commits `ci.yml` pins, and all three repos are public. I ran `pip install -e` for director2 in a venv and exported `ATLAS_BOUNDARY_REPO`, `ATLAS_RDE_REPO` and `D2_HARNESS`. All five suites then passed in 0.4 s to 2.4 s each.
- **CI flag:** `test:proposal-audit` passed with `CI=true` and still failed without it.
- **Everything at once:** as the non-root user with all of the above, `npm run test:full` exited 0 in 21.9 s. The final smoke line was `80 ok, 0 failed`, the same as CI.

## CI compared with the README

- **What CI does** (`.github/workflows/ci.yml`): it runs on `windows-latest` with Node 24 and Python 3.12. It checks out the three sibling repos at pinned commits, maps them to drive `E:` with `subst`, runs `npm ci`, runs `pip install -e` for director2, then runs `npm run test:full`. It sets `CI=true`, `ATLAS_BOUNDARY_REPO`, `ATLAS_RDE_REPO` and `D2_HARNESS`.
- **What the README says:** `npm ci`, then `npm test`. `npm ci` matches. `npm test` is only the first step of CI's `test:full`, which appears in docs/TESTING.md but not in the README.
- **What CI never runs:** `v1:status`, `v1:verify`, `v1:release`, `npm start`, `work:eat`, `economic:scan`, `obligations:*` or `inspect_source`. So nothing in CI would notice gap 1, 2 or 3.
- **Is CI green?** Yes: run 52 on this exact commit passed (https://github.com/NexumCorpus/atlas-station/actions/runs/39319622203). Its log matches my mirrored run: smoke `80 ok`, fleet `SKIP`, and the other suites `ALL PASS`. Runs 47–51 on master, earlier on 2026-10-19, all failed.

## README gaps a stranger hits, most serious first

1. **The "Verify v1" section cannot pass anywhere.** The `operator-doc-truth` check in `scripts/v1-readiness.cjs:76-80` requires the README to contain the string `gpt-5.6-luna`. The README has not contained it since commit 5f73e64 (2026-08-27, "docs: overhaul the Atlas public surface"). The `codex-cli` check also requires a `codex` binary on PATH. Meanwhile the README says "Authenticated Codex/Claude worker routes are disabled by design", and `fleethost.mjs:117` throws for those routes. The README, `v1.contract.json` (`"provider": "codex-cli"`), docs/V1.md and AGENTS.md disagree about what the executive route is.
2. **The organism rehearsal in `v1:verify` and `v1:release` is hardcoded** to `python E:\station\station.py organism run` (`scripts/v1-readiness.cjs:87-91`), with no override variable. It needs the separate NexumCorpus/station repo, which the README never names. On Linux it failed with `can't open file '/home/user/atlas-station/E:\\station\\station.py'`.
3. **`npm start` never starts the fleet sidecar** unless Node lives at `C:\Program Files\nodejs\node.exe` or `NODE_BIN` is set (`main.cjs:15`). `NODE_BIN` is undocumented. When the spawn fails, the supervisor re-queues the restart with `setTimeout(..., 0)` (`main.cjs:105`) and no backoff. In a 40-second headless run it wrote 5,258 lines (2,629 start/exit pairs) to `.atlas/supervisor-registry.ndjson`. Windows users who installed Node with nvm-windows, Volta, Scoop or a per-user installer would hit the same loop.
4. **With `NODE_BIN` set, the sidecar writes runtime state to a hardcoded `E:\atlas-station`.** The path comes from `providers/worktree.mjs:5`, and its `ATLAS_REPO` override is undocumented. On Linux this creates a directory literally named `E:\atlas-station` inside the checkout, which made `git status` dirty. On Windows it would write to drive E:, outside the checkout. 26 `.cjs`/`.mjs` files outside `.atlas/` contain a hardcoded `E:\` or `E:/` path.
5. **The full test surface needs setup the README omits.** That means three public sibling repos at pinned commits, `pip install -e` for director2, and the variables `ATLAS_BOUNDARY_REPO`, `ATLAS_RDE_REPO` and `D2_HARNESS`. Without them, five suites fail on `E:/...` paths.
6. **`test:proposal-audit` fails in a fresh clone unless `CI=true`.** It asserts that no HIGH proposal is pending in `memory/proposals.ndjson`. The committed copy has one, `P-1787721855987`. The test's comment (`tests/proposal-audit-contract.mjs:51-62`) says that ledger is "absent in clean clones", but the file is tracked: `.gitignore` lists `memory/`, but those files were committed anyway. CI passes only because it sets `CI=true`.
7. **The README does not say whether Linux or macOS is supported.** In practice, the test surface works on Linux once gap 5 is handled, and the app launch path does not (gaps 3 and 4).
8. **The cloud `.env` example gives `ATLAS_OPENROUTER_MODEL=<model-id>` with no suggested value**, so a stranger has to pick a model ID with no guidance.
9. **The Architecture section lists `mission.cjs`, which does not exist.** The mission path is `scripts/mission-run.mjs`, which is also what `v1.contract.json` requires.
10. **`inspect_source` does not state its limits in the response.** The response carries `scannedFiles`, `scannedBytes`, `fileLimitReached`, `byteLimitReached`, `skippedOversize`, `resultCount` and `totalMatches`. It does not carry the limits themselves (512 files, 512 KiB per file, 8 MiB total, and results capped at 1–50, in `source-sight.cjs:9-11,55`), and it says nothing about query or path limits.
11. **The `npm test` summary undercounts, and its last section can never fail the run.** `tests/behavioral.mjs:428-429` prints `Results: 78 passed, 0 failed` and exits on failure before section 19 runs (line 431 onward). Those 9 assertions print PASS or FAIL but affect neither the count nor the exit code. Line 335 also prints a PASS line by hand without counting it. That is why the output has 88 PASS lines against "78 passed".
12. **docs/TESTING.md, linked from the README, describes state a stranger cannot reproduce.** It says "the current 14/18 historical rating" needs "three additional evidenced good outcomes", and that `audit:outcomes --strict` "intentionally exits nonzero" while A-132 to A-134 are unresolved. In a clean clone, `audit:outcomes` reports `total: 0`, and `--strict` exits 0. The same doc says the smoke suite "validates that the local Claude sidecar seam is alive" and "depends on an installed local CLI". In fact `tests/smoke.mjs` only `require()`s every root `.cjs` module, and it passed with no CLI installed.
13. **`economic:scan` exits 0 even when every source fails to fetch.** The receipt does record `fetch failed` per source. But its closing line, "No candidate survived deterministic read-only gates", reads like an empty market rather than a failed scan, and the exit code does not tell the two apart.
14. **Failing wing tests leak child processes and wait out their full timeout.** After `test:wing:d2`, `test:wing:felt` and `test:mission` failed on the missing harness, three `python d2-wing.py` processes were still running 5–6 minutes later; I killed them. `test:mission` waited its full 300 s, even though the wing reported `exit: -1` on `init` right away.

## What I could not check

- **The SEC proof (C10) and the bounty scan (C6):** the VM's network policy denies `www.sec.gov` and `algora.io`.
- **Live model routes:** an OpenRouter key costs money, and I had no Ollama install (or the `qwen3.5:9b` model) here. `test:fleet` skips without credentials, in my run and in CI.
- **The app window:** `npm start` ran headless under xvfb for 40 seconds and I did not look at the window itself. The Electron renderer harness and visual tests do pass, as non-root under xvfb.
- **Windows behaviour:** CI covers that, on a runner that has drive `E:` mounted.
